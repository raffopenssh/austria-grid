# austria-power.exe.xyz:8000 — Austrian Energy Infrastructure API

> Machine-readable reference for LLM agents.
> Base URL: https://austria-power.exe.xyz:8000

## GET /api/infrastructure

Returns a GeoJSON FeatureCollection of all Austrian energy infrastructure,
exploded into individual features. Every grouped obstacle (e.g. a windpark row
with 3 turbines) becomes 3 separate Point features with their own coordinates.
Null properties are omitted for compact output.

### Query parameters

| param      | type   | default | description |
|------------|--------|---------|-------------|
| bbox       | string | (all)   | `min_lon,min_lat,max_lon,max_lat` (EPSG:4326) |
| layers     | string | (all)   | Comma-separated layer names |
| categories | string | (all)   | Comma-separated category names |

### Layers (9)

| name               | count  | description |
|--------------------|--------|-------------|
| obstacles          | 6,163  | AustroControl obstacle DB — individual Points for antennas, wind turbines, cable car towers, pylons, cranes, stacks, buildings, etc. Curves also emitted as LineStrings. |
| windparks          | 1,381  | igwindkraft.at — per-turbine positions with year, model, capacity. |
| power_plants       | 4,601  | OSM — solar, hydro, biomass, gas, coal, waste (wind excluded, covered by obstacles). |
| substations        | 513    | Umspannwerke — deduplicated across OSM, grid operators, 380kV nodes. |
| hydropower         | 156    | Major hydropower plants with MW, type, river. |
| transmission_lines | 1,751  | OSM (110–380kV) + 380kV grid edges as LineStrings. |
| onip_powerlines    | 5,263  | ÖNIP high-voltage route waypoints. |
| cross_border       | 9      | Cross-border interconnections AT↔DE/CZ/SK/HU/SI/IT/CH. |
| hydro_connections  | 32     | Inferred hydro plant → substation links. |

### Categories (14)

`wind_energy` · `solar_energy` · `hydropower` · `biomass` · `fossil` · `waste_energy` · `substation` · `telecom` · `power_line` · `cable_infrastructure` · `structure` · `industrial` · `power_generation` · `other`

### Common properties (every feature)

| property | type   | description |
|----------|--------|-------------|
| source   | string | Data origin |
| type     | string | Specific type (e.g. `Antenna`, `Windmill farm`, `solar`, `transformer_station`) |
| category | string | Semantic group (see list above) |
| name     | string | Feature name (when available) |

### Examples

```
# All infrastructure in a bounding box
GET /api/infrastructure?bbox=16.2,48.1,16.5,48.3

# Wind turbines + substations only
GET /api/infrastructure?bbox=16.2,48.1,16.5,48.3&layers=obstacles,substations&categories=wind_energy,substation

# All solar plants in Burgenland area
GET /api/infrastructure?bbox=15.8,46.8,17.2,48.2&categories=solar_energy

# Everything for a LiDAR/ortho tile (~1km bbox)
GET /api/infrastructure?bbox=16.35,48.20,16.36,48.21

# All transmission lines nationwide
GET /api/infrastructure?layers=transmission_lines

# Just telecom towers and industrial structures
GET /api/infrastructure?bbox=16.0,48.0,16.5,48.5&categories=telecom,industrial
```

## GET /api/infrastructure/stats

Summary counts by source, category, and type. No parameters.

## Data volume (~19,900 features)

- 6,163 AustroControl obstacles (1,713 antennas, 1,620 wind turbines, 1,212 cable car towers, 1,093 transmission line pylons, 268 catenary, 70 poles, 68 buildings, 30 stacks, 30 masts, …)
- 5,263 ÖNIP powerline route points
- 4,601 OSM power plants (3,513 solar, 779 hydro, 127 biomass, 70 fossil, 8 waste)
- 1,381 windpark registry turbines
- 1,291 OSM transmission lines + 460 380kV grid edges
- 513 substations / Umspannwerke
- 156 major hydropower plants
- 41 connection lines (cross-border + hydro-grid)

## Notes for ML / random forest usage

- `height_agl_m` / `elev_m` directly correspond to LiDAR DSM/DTM signals
- `rotor_diameter_m` / `hub_height_m` predict wind turbine signatures in imagery
- `area_sqm` helps bound expected footprints
- `category` is the best coarse label for classification targets
- `capacity_mw` available for wind turbines, power plants, substations, hydropower
- `year` available for ~95% of wind turbines
- Use small bbox queries matching your tile extent for per-tile enrichment
- LineStrings indicate linear elevated structures in LiDAR/imagery
- `lighted` indicates night-visible markers on obstacles

## Market analytics API (ENTSO-E history since 2023-01)

Pre-aggregated market analytics from stored ENTSO-E data (day-ahead prices,
generation per PSR type, load; 15-min resolution, aggregated hourly for
cross-year comparability). All responses cached 1h server-side.

- GET /api/analytics/summary — yearly KPIs: avg price, negative-price hours, hours >200 EUR, solar/wind peaks
- GET /api/analytics/negative-prices — monthly/yearly negative-price hours + hour-of-day histogram per year
- GET /api/analytics/capture-rates — monthly solar & wind capture prices and capture rates (value factors) vs baseload
- GET /api/analytics/battery-arbitrage?hours=1..6 — perfect-foresight daily arbitrage spread and EUR/MW revenue for an N-hour battery (90% efficiency, 1 cycle/day)
- GET /api/analytics/duck-curve?months=04,...,09 — avg hour-of-day profile per year of load, solar, wind, run-of-river, residual load + price profile
- GET /api/analytics/import-dependency — monthly generation vs load balance, renewable share of load, fossil share, surplus hours, cross-border flows (since 2026-01)

Dashboard: GET /analytics (HTML)

## Future grid API (Zukunftskarte 2040)

Reverse Standortanalyse: instead of scoring one address, a background job
(future_grid_planner.py, hourly cron) walks all of Austria on an H3 hex grid
(res 7, ~5 km2, 16,412 cells) and computes per cell:

- demand_gwh / demand_2040_gwh: annual demand, national ENTSO-E load (trailing
  365d) distributed by Kontur 400m population raster; 2040 = +45% (OeNIP)
- supply_gwh + supply_by_type: annual generation of ALL currently used plant
  types (hydro run-of-river/reservoir/pumped storage, wind, solar incl.
  population-distributed rooftop share, gas, biomass, waste, coal, other),
  calibrated so per-type totals match ENTSO-E trailing-365d generation
- gap_gwh / gap_2040_gwh: demand minus supply (positive = deficit)
- recommendations: sized build-out plan per cell (solar_rooftop, solar_ground,
  wind, battery, hydro_repowering, grid_import, grid_upgrade) considering
  state capacity factors, INSPIRE protected areas, grid headroom of the
  nearest e-control transformer station, and existing local buildout

Endpoints:
- GET /api/future-grid?state=&tech=&min_gap=&compact=1 — all computed cells (~12 MB full, use compact=1 or filters)
- GET /api/future-grid/stats — job progress + national aggregates (deficit TWh, recommended MW per tech)

Map: enable "Zukunftskarte 2040" layer on / (modes: 2040 balance, recommended tech, supply, demand).
